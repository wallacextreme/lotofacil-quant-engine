# 0. MANDATO PRINCIPAL

Não trate este projeto como um simples "gerador de números".

Trate-o como um:

> **Sistema de análise estatística e otimização combinatória para construção de conjuntos de combinações sob restrições configuráveis.**

O sistema não deve alegar prever o próximo sorteio, descobrir dezenas "garantidas", aumentar matematicamente a probabilidade fundamental de uma combinação individual ou produzir vantagem probabilística comprovada sem evidência estatística adequada.


# 8. PROBABILIDADE COMBINATÓRIA

Implementar:

$$
C(n,k)=\frac{n!}{k!(n-k)!}
$$

com método numericamente seguro.

Calcular:

$$
C(25,15)=3.268.760
$$

Probabilidade de uma combinação específica:

$$
P=\frac1{3.268.760}
$$

Implementar também:

$$
P(X=k)=
\frac{C(K,k)C(N-K,n-k)}
{C(N,n)}
$$

Não cometer o erro conceitual de dizer que a distribuição hipergeométrica representa a probabilidade de uma combinação específica.

* identificação de inconsistências;
* otimização do algoritmo;
* revisão de segurança;
* análise de performance;
* testes;
* regressão;
* decisões que possam gerar dívida técnica.

### Não gaste esforço excessivo com:

* microalterações visuais;
* CSS trivial;
* texto cosmético;
* renomeações sem impacto;
* refatorações puramente estéticas.

Priorize engenharia de alta qualidade.

---

# 51. REGRA DE MODIFICAÇÃO MÍNIMA

Quando existir código funcional:

não reescrever sem necessidade.

Preferir:

```text
PATCH
```

a:

```text
REWRITE
```

Preservar:

* funcionamento;
* layout;
* estilos;
* filtros;
* fluxos existentes;
* dados;
* compatibilidade.

Somente alterar o necessário.

# 55. REGRA FINAL

Não entregue apenas código que compila.

Antes de considerar o projeto concluído:

1. executar aplicação;
2. importar dataset de teste;
3. executar análise;
4. gerar jogos;
5. validar jogos;
6. verificar Hamming;
7. verificar persistência;
8. testar restauração;
9. executar testes automatizados;
10. executar build de produção.

Depois produzir um relatório final:

```text
IMPLEMENTATION_FINAL_REPORT.md
```

contendo:

```text
Arquitetura
Funcionalidades
Testes
Performance
Limitações
Riscos
Pendências
Instruções de execução
Instruções de build
Estado do projeto
```

Não inventar resultados.

Não esconder falhas.

Não ignorar inconsistências matemáticas.

Não violar filtros para "conseguir gerar jogos".

Quando uma configuração for matematicamente inviável, o sistema deve detectar e explicar a inviabilidade.

O objetivo é construir um **software de engenharia combinatória auditável**, e não um simulador que apenas produza resultados visualmente convincentes.
